
# Learning Reflection

> Please use the below questions as guidelines to help you think and 
> plan your Learning Reflection Report

## 1. How was your experience testing the given Webapp?
- Testing GitLab was an interesting and educational experience. 
  The application is large and complex, which made it challenging 
  to know where to start. However, by focusing on specific pages 
  such as Register, Project, and Issue pages, the process became 
  more manageable. It was helpful to explore the application 
  manually before writing the test cases to understand the expected 
  behavior of each feature.

## 2. How did you write or manage your test case? Describe the process.
- I followed the template provided in 01_Template_TestSuit.txt and 
  used 02_LoginPage.txt as a reference example. First I explored 
  each page in GitLab to understand its functionality. Then I 
  identified positive and negative test scenarios. Finally I wrote 
  step-by-step test cases using the predefined format with Settings, 
  Variables, and Test Cases sections. I organized test data as 
  variables to make the test cases easier to maintain and reuse.

## 3. Do you recommend any other tools or styles for Test case management?
- Yes, I would recommend tools like TestRail or Zephyr for more 
  structured test case management in professional projects. These 
  tools allow linking test cases to requirements and tracking 
  test execution results. For agile projects, managing test cases 
  directly in Jira with Zephyr integration works well because it 
  connects test cases to user stories and bug reports in one place.

## 4. Which IDE (Visual Code or Atom or else) have you used to edit files?
- I used Visual Studio Code to edit all the test case files and 
  reports in this assignment. It is a lightweight and powerful 
  editor with good support for Markdown and plain text files. 
  Extensions like Markdown Preview made it easy to check the 
  formatting of the bug report and learning reflection files.

## 5. Did you find any trouble? How did you solve the trouble?
- The main challenge was understanding the correct format for 
  writing test cases since I had not used this style before. 
  I solved this by carefully studying the example file 
  02_LoginPage.txt and following its structure exactly. 
  Another challenge was identifying good negative test cases, 
  which I solved by thinking about what could go wrong from 
  a user perspective.

## 6. Did you find any trouble using GitHub? Have you used GitHub before? Where?
- I had used GitHub before for storing course assignments and 
  small personal projects. In this assignment I created a new 
  repository, added a README with my full name, and uploaded 
  all project files manually. I did not encounter major issues 
  but had to remember not to upload the ZIP file directly as 
  instructed in the assignment guidelines.

## 7. If in the future you need to automate these test cases, which framework or language will you use and why?
- I would use Robot Framework with Python because it uses a 
  keyword-driven approach that is very similar to the manual 
  test case format used in this assignment. The transition from 
  manual to automated tests would be straightforward since the 
  structure is already familiar. For more modern web testing 
  Cypress would also be a strong choice due to its fast execution 
  and easy setup for JavaScript developers.

## 8. List the most in-demand skills and competencies in software testing
- After searching on LinkedIn and Glassdoor for Tester and 
  Automation Tester positions, the most in-demand skills are:
  - Test automation frameworks: Selenium, Cypress, Playwright
  - Programming languages: Python, JavaScript, Java
  - API testing tools: Postman, REST Assured
  - CI/CD tools: Jenkins, GitHub Actions, GitLab CI
  - Test management tools: Jira, TestRail, Zephyr
  - Performance testing: JMeter, k6
  - Soft skills: attention to detail, analytical thinking, 
    clear communication, and ability to work in agile teams

## 9. Which technical and soft skills do you need to fill in your resume for a career in Software Testing?
- Technical skills I need to develop further:
  - Learn at least one automation framework such as Cypress or Selenium
  - Improve Python or JavaScript programming skills
  - Get hands-on experience with API testing using Postman
  - Learn how CI/CD pipelines work in practice
- Soft skills to develop:
  - Improve ability to write clear and detailed bug reports
  - Practice communicating testing results to non-technical team members
  - Develop more structured and systematic thinking when designing test cases

## 10. Learning Reflection - Free words
- This project was a valuable practical exercise that helped connect 
  theoretical testing knowledge with real-world application. Writing 
  manual test cases for a live application like GitLab made the 
  concepts of positive and negative testing, preconditions, and 
  postconditions much more concrete than just reading about them 
  in theory. The bug report section was especially useful because 
  it taught me how to document issues clearly and professionally. 
  Overall the assignment gave me a good foundation for understanding 
  what software testers do in their daily work and what skills 
  I need to develop further to work in this field professionally.
